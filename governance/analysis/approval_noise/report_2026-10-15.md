# 核准噪音量測結果（2026-10-15）

**這份報告只產生證據，不改分析器，也不建議放寬任何工具**；放寬與否是之後 Roy 逐個決定的事。
方法在看資料前寫定（`mapping.md`、`standard.md`），並經兩輪小o 事前審查修訂；本報告是第二次標記（第一次作廢，見最後一節）。

## 一句話

在 Roy 最近 30 天的 Claude Code 工作裡，現行分析器對 **68.3%** 的可對應工具呼叫要求核准；其中被問到的呼叫有 **25.2% 到 65.0%**
被標記者認為不必問（區間來自「無法判定」佔 39.8%）。**噪音大多集中在 Bash，而 Bash 在這種去識別下大約四成無法判定**，所以 Bash 的噪音
只能給區間，不能給點估計。有幾類是明確、量小的噪音（沒帶路徑的 grep／glob、任務清單工具）。

## 解讀（每一句都限定在上表與下列限度內）

1. **最大的量在 Bash，但 Bash 最看不清。** 抽到的 90 筆裡，必要與不必要各 24、無法判定 42。無法判定的主因是指令詞的作用被隱去
   （直譯器跑腳本 13、指令內容有隱藏部分 12、其他）。因此 Bash 的噪音只能給寬區間（依層權重加權後，被問到的 Bash 裡不必要的比例約 **26% 到 70%**，下界把無法判定當必要、上界當不必要），不能說一個數字。
   要把 Bash 看清，需要比這種去識別更多的資訊，也就是**讓有權看原始指令的人（Roy 自己，或你同意的方式）標記一小批**。
2. **檔案類被問到的呼叫，大多數確實必要**（44 筆中 35 筆）：35 筆都是寫入或建立工作區外的檔案（`str_replace` 21、`create` 14）。不必要的 9 筆都是「讀取工作區外的非祕密檔案」（`view`），
   這是 `standard.md` 的一個**有意選擇**（更嚴的團隊會不同意）。
3. **明確、量小的噪音**：沒帶路徑的 `grep`／`glob` 與 `task_tracker`，抽到的 59 筆裡 58 筆被標為不必要。這三類加起來只有 197 筆（1.1%），
   所以放寬它們不會明顯降低整體核准量；但它們是同一個結論（`path` 欄位缺漏、`command` 欄位名稱）造成的，看起來是分析器規則的副作用，而不是風險判斷。
4. **MCP 看不出來**：44 / 50 無法判定（只有名稱，沒有參數與讀寫性質）。這是 O3（MCP 工具准入）要處理的問題，不是這份資料能回答的。
5. **沒被問到的動作裡，沒有標記者認為必要的**（0 / 90，都是工作區內的讀與搜尋）。這個樣本小，只能說「沒有看到漏問的證據」，不能說「沒有漏問」。
6. **探索性的候選（不是結論）**：只由特徵推出的一條簡單規則——Bash 動作的作用類別只含讀取、版本控制唯讀、測試／建置工具，且沒有隱藏部分、
   沒有重導向、沒有區外路徑、沒有送出資料、沒有祕密路徑——在全母體命中 **892 / 9,087（9.8%）**。它是**看過標記之後才提出的**，只對 10 筆抽樣驗證過（10 / 10 被標為不必要）；
   10 筆只能支持「沒看到反例」，不能支持「很準」。若要認真考慮它，需要更多樣本與你自己的判斷。

## 限度（請一併讀）

- 標記者是模型（小o），與小c 是不同廠牌但仍是模型；標準是**一個**合理的標準，不是唯一的。
- 這是 Claude Code 的使用，不是 OpenHands agent 的行為，也偏向 Roy 本人的研究型工作與習慣。
- `cwd` 為家目錄或更高層的對話（`broad`）裡，「在工作區內」幾乎涵蓋整顆磁碟，**檔案類動作的免核准比例被高估**；沒有外生的更嚴格定義可用。
- 沒有「檔案是否被版本控制追蹤」的資訊，所以把「可由版本控制回復」當作對工作區內編輯的一般性假設。
- 區間是近似法；各層樣本小（最大層 50 筆）。
- 去識別讓部分 Bash 無法判定，並以區間呈現；Bash 解析不是完整的 shell 解析（見 `replay.py` 與其測試的涵蓋範圍）。
- 這份資料不涉及：這些必要動作是否該用別的機制（沙盒、網路政策）擋，不評論。

## 方法的過程（為了誠實）

- 方法文件在看資料前寫定，經小o 兩輪事前審查（抓到：W2 工作區定義有內生性並已刪除、相對路徑沒依 cwd 轉絕對、估計量與抽樣權重沒寫清楚、
  Bash 去識別資訊不足、工具名稱沒去識別、取樣上限與權重不相容、MCP 不該預先排除等）。
- **第一次標記作廢**：標記後發現我的 Bash 特徵有 bug（一段指令只要沒新增任何作用類別，就被誤判為「無法分類」，
  所以 `cd x && ls` 這種唯讀指令也被標成未知，Bash 的無法判定被人為撐大）。已修正、加回歸測試（把舊 bug 放回去測試會失敗），**整個流程重跑**，第一次的結果不採用。
  第一次的區間是 A 12.6% 到 69.4%、無法判定 56.7%，現在是 25.2% 到 65.0%、39.8%，可見這個 bug 的影響。
- 標準 `standard.md` 在兩輪都在看資料前寫定，沒有因結果修改。
