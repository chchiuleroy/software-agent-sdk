# Claude Code 工具 → OpenHands 內建工具對應表與量測設計（第 2 版，2026-10-15，依小o 事前審查修訂；仍在看資料之前）

分析器（`RoyPathPayloadSecurityAnalyzer`）依「工具身分」與欄位判斷風險，所以重放前要把 Claude Code 的工具呼叫
換成 OpenHands 的內建工具。**這張表與下面的估計設計是方法的一部分，已被審查。**

## 對應表

| Claude Code 工具 | OpenHands 工具與動作 | 帶入的欄位 | 備註 |
|---|---|---|---|
| `Read` | `file_editor`，`command="view"` | `path` ＝ `file_path` | 分析器只讀 `path`，`command` 不影響判定（小o 已核對） |
| `Edit` | `file_editor`，`command="str_replace"` | `path` ＝ `file_path` | 只取路徑，不取內容 |
| `Write` | `file_editor`，`command="create"` | `path` ＝ `file_path` | |
| `NotebookEdit` | `file_editor`，`command="str_replace"` | `path` ＝ `notebook_path` | 近似 |
| `Grep` | `grep` | `path`（沒給＝`None`） | 沒給路徑時分析器回 UNKNOWN |
| `Glob` | `glob` | `pattern`、`path`（沒給＝`None`） | `pattern` 是否可跳出路徑會影響判定 |
| `Bash` | `terminal` | `command` | 有 `command` 欄位 → 分析器一律 HIGH |
| `TaskList`、`TaskGet` | `task_tracker`，`command="view"` | | **近似**；分析器因有 `command` 欄位回 HIGH |
| `TaskCreate`、`TaskUpdate`、`TodoWrite` | `task_tracker`，`command="plan"` | | **近似**；同上 |
| `mcp__*`（任何 MCP 工具） | 第三方／MCP 工具 | 無 | 分析器設計上一律 UNKNOWN。**留在主要分母**，與其他工具一樣依 `standard.md` 標記（第 1 版預先排除是錯的） |
| `WebSearch`、`WebFetch` | **無對應** | | 是否可對應 `browser_use` 沒有證據，維持無對應並報告覆蓋率 |
| `Skill`、`ToolSearch`、`Agent`（子代理）、`AskUserQuestion`、`ExitPlanMode` 等 | **無對應** | | Claude Code 自己的控制流程 |

**相對路徑一律先依該筆紀錄自己的 `cwd` 轉成絕對路徑**再交給分析器（`file_editor` 的契約是絕對路徑，分析器對 `file_editor` 不做相對轉換）。
無法轉成絕對路徑（相對路徑但紀錄沒有 `cwd`）的，計為 `unresolved`，不丟給分析器，並在覆蓋率報告列出。

## 工作區根目錄

只用一種定義：**每筆紀錄自己的 `cwd`**。第 1 版另有 W2（本次所有被碰觸路徑的最深共同祖先），**已刪除**：
小o 指出它由被評估的路徑反推邊界，內生地把這些路徑全部納入工作區，只會機械性增加 LOW，方向也與當時文字相反。

取而代之的是**用 `cwd` 的廣度分層**（它在動作之前就已存在，所以不再由被評估的路徑反推；但它不是隨機指派，從家目錄或從專案啟動
與任務類型、工具使用相關，所以分層只描述條件分布，**不支持「改用較窄工作區會改變多少」這類因果結論**）。`broad` 指 `cwd` 是家目錄本身或它的任何上層（含磁碟根目錄），
不是「路徑層數少」：

- `broad`：`cwd` 是家目錄或更高層（這位使用者常從家目錄啟動 Claude Code）。此時「在工作區內」幾乎涵蓋整顆磁碟，
  **檔案類動作的免核准比例會被高估（噪音被低估）**。
- `project`：`cwd` 是專案子目錄。
- 報告把所有結果依 `cwd_class` 分開呈現，並明說 `broad` 層的限度。沒有外生的「更嚴格」工作區可用，所以不假裝提供敏感度範圍。

## Bash 特徵（在本機由完整指令算出，只輸出布林、計數與固定詞彙）

依 `standard.md`「標記者看到什麼」。第 1 版只留指令頭與旗標，小o 指出那會讓大多數 Bash 落入 CANNOT_TELL；
所以改成**先在本機解析完整指令**，輸出作用類別（read／write／delete／install／network／…）、路徑參數落在工作區內外的個數、
重導向目的地是否在區外、是否像祕密路徑、是否送出資料等；**仍不輸出任何路徑、字串、引數或腳本名稱**。
指令詞只允許出自事先寫死的詞彙表，其餘一律寫成 `other`。

## 估計設計（第 1 版沒寫清楚；小o 指出）

**母體**：最近 30 天（以每筆紀錄自己的時間戳篩選）Claude Code 對話中，已去重（以 `tool_use` id）的工具呼叫。

**覆蓋率**（一定報告）：全部呼叫中，`mapped`、`mcp`、`no_mapping`（逐個工具名列）、`malformed`、`unresolved` 各占多少。
結論只限定於「可對應的呼叫」，不外推到整個工作負載。

**主要估計量**（三個，先寫死）：

- `P(asked)`：在可對應呼叫（含 MCP）中，分析器要求核准的比例。這是確定性的，直接用全母體計數，無抽樣誤差。
- `A`＝**可避免核准比例**：在「分析器要求核准」的呼叫中，標記為 NOT_NECESSARY 的比例（以層權重加權）。CANNOT_TELL 單獨列，給下界（全算必要）與上界（全算不必要）。
- `N`＝**噪音率** ＝ `P(asked) × A`：在全部可對應呼叫中，被問到而其實不必要的比例，同樣給區間。
- 對照：在「分析器**不**要求核准」的呼叫中，標記為 NECESSARY 的比例（疑似該問而沒問，小樣本，只作描述）。

**分層與權重**：層＝(分析器要求核准與否) × (映射後的工具) × `cwd_class`。每層母體筆數 `N_h`、樣本數 `n_h`，估計量用 `N_h/n_h` 加權。
**抽樣程序（可重現）**：每層內**簡單隨機抽樣、每筆納入機率相等**（所以 `N_h/n_h` 是正確權重）：把該層全部呼叫依 `i` 排序，用 `random.Random(20261015)`
洗牌後取前 `n_h` 筆；層內不足 `n_h` 就全取。**不設「每個對話最多取幾筆」的上限**（第 1 版有，與 `N_h/n_h` 權重不相容；小o 指出）。
**群聚**：同一個對話內的呼叫高度相似，不視為獨立；信賴區間用**以對話為單位的群聚 bootstrap**（1000 次；在每層內以對話為單位重抽樣本單位，權重固定）。
這是近似法，報告會這樣說明。
**樣本量**：先全量重放得到各層母體筆數（不涉及任何標記），再決定各層樣本數；小於等於 15 筆的層全取並只作描述，不算區間。
目標：主要層（Bash、檔案類）的 `A` 的 95% 區間半寬不超過 15 個百分點；達不到就如實報告區間，不補抽樣到「好看」。

**標記者一致性**：另取 20 筆（分層）由小o 在另一次獨立呼叫中**重複標記**，報告重複標記的一致率（同一位標記者的自我一致性；不是人與人的一致性）。

## 限度

- Claude Code 的工具使用不等於 OpenHands agent 的行為，也偏向 Roy 的研究型工作與他自己的工作習慣。
- 沒有「檔案是否被版本控制追蹤」的資訊；`broad` 層的工作區定義高估免核准。
- 標記者是模型（小o），且去識別會讓部分動作無法判定。
